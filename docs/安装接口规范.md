# 安装接口规范 v1.0

> **定位**: 安装器与 Agent 之间的接口契约。安装器冻结后，所有新 Agent 版本必须向后兼容此规范。
>
> **版本**: 1.0 (2026-05-14 冻结)
>
> **原则**: 安装器是部署工具，不是 Agent 的一部分。安装器接口只定义"如何把 Agent 部署到一台机器上"。

---

## 1. 部署目标

安装器在目标机器上建立以下目录结构：

```
{INSTALL_DIR}/
├── node-agent              # Agent 主二进制 (Linux) 或 node-agent.exe (Windows)
├── agent.yaml              # Agent 配置文件
├── certs/                  # 证书目录（安装器创建空目录）
└── ddns_cache.yaml         # DNS 配置缓存（Agent 运行时自动生成）
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `INSTALL_DIR` | Linux: `/opt/ddns-agent` / Windows: `C:\ddns-agent` | 用户可自定义 |
| `CONFIG_PATH` | `{INSTALL_DIR}/agent.yaml` | Agent 读取配置的固定路径 |
| `CERT_PATH` | `{INSTALL_DIR}/certs` | Agent 默认证书目录 |

## 2. 配置文件接口 (agent.yaml)

安装器写入的配置文件，Agent 启动时必须能正确解析。

### 2.1 格式

```yaml
# agent.yaml — ddns-manager Node Agent 配置
manager_url: "https://manager.example.com:30443"  # 管理端地址（必填）
node_id: "client-a"                            # 节点标识（必填）
fingerprint: "sha256:abc123..."                # 机器指纹（必填）
password: "a1b2c3..."                          # 节点密码（必填，hex编码的随机16字节）
cert_path: "/opt/ddns-agent/certs"             # 证书存储目录（可选）
pfx_password: ""                               # PFX 证书密码（可选）
verify_ssl: true                               # 是否验证管理端 TLS 证书（可选）
iis_cert_bindings: []                          # IIS 证书绑定（可选，Windows专用）
```

### 2.2 字段契约

| 字段 | 类型 | 必填 | 说明 | Agent 侧约束 |
|------|------|------|------|-------------|
| `manager_url` | string | ✅ | 管理端 URL，含协议和端口 | 心跳请求的目标地址 |
| `node_id` | string | ✅ | 节点唯一标识 | 心跳 `NodeID` 字段 |
| `fingerprint` | string | ✅ | `sha256:{hostname+machine_id}` | 心跳 `Fingerprint` 字段 |
| `password` | string | ✅ | hex 编码的 16 字节随机数 | 心跳认证 Bearer Token |
| `cert_path` | string | ❌ | 证书存储绝对路径 | `ConfigPath` 字段 |
| `pfx_password` | string | ❌ | 默认 PFX 密码 | `PFXPassword` 字段 |
| `verify_ssl` | bool | ❌ | 默认 true | TLS 客户端校验开关 |
| `iis_cert_bindings` | array | ❌ | IIS 绑定列表 | 仅 Windows Agent 使用 |

### 2.3 格式兼容性

- Agent 必须同时支持 YAML 和 JSON 格式的 `agent.yaml`
- 新增字段必须为可选字段（带默认值），安装器不感知的字段 Agent 自行处理
- 安装器绝不删除或修改已有的 `agent.yaml`（升级场景保留配置）

## 3. Agent 二进制接口 (CLI)

安装器通过 CLI 参数和退出码与 Agent 交互。

### 3.1 必选参数

| 参数 | 行为 | 使用场景 |
|------|------|----------|
| `-heartbeat` | 发送单次心跳后退出 | systemd timer / 计划任务 |
| `-daemon` | 守护进程模式，每 5 分钟心跳 | Windows Service / 长驻进程 |
| `-version` | 打印版本号到 stdout 后退出 (exit 0) | 安装器验证 / 用户查看 |
| `-dir <path>` | 覆盖默认安装目录 | 自定义安装路径 |

### 3.2 `-version` 输出格式

```
node-agent v{version}
Publisher: Lanxun CO.,Ltd.
```

版本号从 ldflags `-X main.version=x.y.z` 注入。

### 3.3 `-heartbeat` 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 心跳成功 |
| 1 | 心跳失败（网络/认证错误） |
| 其他 | 致命错误（配置文件损坏等） |

### 3.4 文件系统约束

- Agent 运行时不依赖当前工作目录（可通过 `-dir` 指定基准路径）
- Agent 通过 `filepath.Join(os.Args[0]的目录, "..")` 定位安装目录（备选），优先使用 `-dir`
- Agent 的缓存文件（ddns_cache.yaml）必须写入安装目录内，不泄漏到 `/tmp` 等临时目录

## 4. 管理端接口 (Manager API)

安装器和 Agent 共同依赖的管理端 API。

### 4.1 版本探测

```
GET /api/ping
→ {"status":"ok","version":"1.5.29"}
```

| 约束 | 说明 |
|------|------|
| `version` 字段 | 语义化版本号 `x.y.z`，不含 `v` 前缀 |
| 响应格式 | JSON，Content-Type: application/json |
| 安装器用途 | `detect_version()` 获取最新 Agent 版本号 |

### 4.2 二进制下载

```
GET /bin/node-agent-v{ver}-{os}-{arch}
→ 二进制流 (application/octet-stream)

GET /bin/ddns-installer-v{ver}-{os}-{arch}
→ 安装器二进制

GET /bin/install.sh
→ 一键安装脚本
```

| 约束 | 说明 |
|------|------|
| `{ver}` | 语义化版本号，不含 `v` 前缀 (如 `1.6.30`) |
| `{os}-{arch}` | Go 标准平台名: `linux-amd64`, `linux-arm64`, `windows-amd64` |
| 版本来源 | `VERSION=1.6.30` 环境变量 → `/api/ping` agent_version → `/api/ping` version |
| install.sh | 下载安装器 + Agent 到同目录, 通过 `-agent-file` 传给安装器, 安装器不再负责HTTP下载 |

### 4.3 节点注册

```
POST /api/register
Content-Type: application/json

{
  "node_id": "client-a",
  "fingerprint": "sha256:abc123...",
  "password": "a1b2c3..."
}

→ 200 {"node_id":"client-a","status":"pending_approval"}
→ 409 {"error":"节点已注册"}
→ 400 {"error":"node_id 和 fingerprint 为必填项"}
```

| 约束 | 说明 |
|------|------|
| `node_id` | 非空字符串，安装器提示用户输入 |
| `fingerprint` | 格式 `sha256:{hex}`，安装器通过 `generateFingerprint()` 生成 |
| `password` | hex 编码的 16 字节随机数，安装器通过 `generatePassword()` 生成 |

### 4.4 指纹查询（安装器预检）

```
GET /api/nodes/{node_id}/fingerprint
→ {"exists":true,"fingerprint":"sha256:abc..."} 或 {"exists":false}
```

## 5. 系统服务接口

### 5.1 Linux (systemd)

**Service 单元** (`/etc/systemd/system/node-agent.service`):
```ini
[Unit]
Description=ddns-manager Node Agent
After=network-online.target

[Service]
Type=oneshot
ExecStart={INSTALL_DIR}/node-agent -heartbeat
```

**Timer 单元** (`/etc/systemd/system/node-agent.timer`):
```ini
[Unit]
Description=ddns-manager Node Agent Timer

[Timer]
OnBootSec=30s
OnUnitActiveSec=5min
RandomizedDelaySec=30s

[Install]
WantedBy=timers.target
```

| 约束 | 说明 |
|------|------|
| `ExecStart` | 必须使用绝对路径 `{INSTALL_DIR}/node-agent -heartbeat` |
| Timer 周期 | 5 分钟 ± 30 秒随机延迟，避免惊群 |
| 服务类型 | Type=oneshot，非 forking/notify |
| 启动方式 | `systemctl enable --now node-agent.timer` |

### 5.2 Windows

**服务名**: `node-agent`
**显示名**: `ddns-manager Node Agent`
**启动类型**: `auto`（自动启动）
**命令行**: `"{INSTALL_DIR}\node-agent.exe" -daemon`
**失败恢复**: 5 秒后重启，24 小时内重置计数

| 约束 | 说明 |
|------|------|
| 二进制路径 | 必须用双引号包裹的绝对路径 |
| 工作目录 | 不设置（Agent 通过 `-dir` 默认值定位） |
| 服务账户 | LocalSystem |

## 6. 机器指纹算法

### 6.1 算法

```
fingerprint = "sha256:" + SHA256(hostname + machineID)
```

### 6.2 machineID 获取

| 平台 | 来源 | 实现 |
|------|------|------|
| Linux | `/etc/machine-id`（去空白） | `os.ReadFile` |
| Windows | 注册表 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` | `golang.org/x/sys/windows/registry` |
| 回退 | 纯 hostname | `getMachineID()` 返回 error 时 |

### 6.3 约束

- 禁止使用外部工具（PowerShell、WMI、dmidecode）
- 同一台机器重装系统后指纹会变化（machine-id / MachineGuid 重置）
- 同一台机器重装本软件指纹不变（`/etc/machine-id` 不受软件卸载影响）

## 7. 兼容性矩阵

| 接口版本 | 安装器版本 | Agent 最低版本 | Manager 最低版本 |
|----------|-----------|---------------|-----------------|
| 1.0 | ≥1.0.0 | ≥1.5.29 | ≥1.5.29 |

### 7.1 向后兼容规则

1. **安装器不感知 Agent 新增的配置字段** — Agent 自行处理未知字段
2. **Agent 必须在 `-version` 返回语义化版本号** — 安装器可能用于诊断
3. **`agent.yaml` 格式为 YAML（JSON 超集）** — Agent 必须用 `yaml.Unmarshal` 而非 `json.Unmarshal`
4. **新增 CLI 参数不得影响现有参数行为** — `-heartbeat`、`-daemon`、`-version` 语义不可变
5. **二进制下载路径不变** — `GET /bin/node-agent-{os}-{arch}` 始终有效

### 7.2 不允许的破坏性变更

- ❌ 修改 `agent.yaml` 必填字段名
- ❌ 修改 `-heartbeat` CLI 参数语义
- ❌ 修改 `/api/register` 请求体格式
- ❌ 改变 systemd 服务名或 timer 名
- ❌ 改变安装目录默认路径
- ❌ 改变指纹算法（会导致所有节点需要重新注册）

---

## 8. 安装器冻结声明

安装器 v1.0.0 代码路径 `cmd/installer/main.go` 自本规范发布之日起冻结。

**可以改的**:
- 依赖库安全更新（`go get -u` 小版本）
- 文档注释

**不能改的**:
- 接口逻辑（任何影响上述契约的行为变更）
- CLI 参数语义
- 文件写入路径
- API 调用格式

**改接口 = 发新版安装器**: 如需修改接口，必须更新本规范文档、升级安装器主版本号（1.0.0→2.0.0），并确保新旧 Agent 都能工作。
